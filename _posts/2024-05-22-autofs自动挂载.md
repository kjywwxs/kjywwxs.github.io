### 功能概述

- 自动挂载文件系统，访问尚未被挂载的文件系统，如果写在autofs配置文件里,则会自动挂载
- 自动卸载文件系统，某个已挂载的文件系统一段时间未使用，则自动卸载

autofs相当于省去手动mount/umount这一步，超时断连，用时重连，**用客户端略微增加的延迟换来网络和服务器资源的节省**

相比于其他那些开机自动挂载的方式，autofs更加灵活

下面是官方提供的说明

The goal of autofs is to provide on-demand mounting and race free automatic unmounting of various other filesystems. This provides two key advantages:

- There is no need to delay boot until all filesystems that might be needed are mounted. Processes that try to access those slow filesystems might be delayed but other processes can continue freely. This is particularly important for network filesystems (e.g. NFS) or filesystems stored on media with a media-changing robot.

- The names and locations of filesystems can be stored in a remote database and can change at any time. The content in that data base at the time of access will be used to provide a target for the access. The interpretation of names in the filesystem can even be programmatic rather than database-backed, allowing wildcards for example, and can vary based on the user who first accessed a name.

autofs 的目标是提供按需挂载和无竞争的自动卸载各种其他文件系统的功能。这带来了两个关键优势：

不需要在启动时等待所有可能需要的文件系统挂载完毕。尝试访问这些较慢文件系统的进程可能会被延迟，但其他进程可以自由继续运行。这对于网络文件系统尤为重要。

文件系统的名称和位置可以存储在远程数据库中，并且可以随时更改。访问时会使用数据库中当前的内容来提供访问目标。文件系统中名称的解释甚至可以是程序化的，而不是基于数据库的。（这一块笔者还没有实践过）

`systemctl start|stop|reload|status autofs.service`


### 安装配置

`yum -y install autofs` (centos为例)

>内网环境没法访问公网的yum源，可参考以下链接配置yum源
https://blog.csdn.net/qq_43475285/article/details/129479198
查看本机yum源
`cat /etc/yum.repos.d/*.repo`

配置文件位置（主映射文件默认位置）
`/etc/auto.master`

**主映射配置格式如下**
`mount-point [map-type[,format]:]map [options]`
- mount-point ：挂载点，如果为`/-`,表示直接映射，具体的挂载点在子配置文件中配置;如果为某个目录，如`/share`,同时子配置文件的key设置为`b`,那么挂载点为`/share/b`，这种是间接映射
- map-type：系统支持的映射类型的一种。如file，program，yp，nisplus，hesiod，ldap或ldaps，multi，dir。
- format：映射数据的格式，有sun，hesiod和amd。
- map：子映射文件的文件名**（必填项）**
- options：一些可选选项，如下表


|  选项 |  说明 |
| ------------ | ------------ |
|   -t,<br> --timeout 单位s|  设置映射条目的过期超时。此选项可用于覆盖在命令行或配置中给出的全局默认值。 |
|...|...|

>主映射文件中可配置内置映射，如
`/net -hosts`
当访问主映射中的/net/myservice时，autofs会寻找主机名为myservice的服务器，并挂载/net/myservice。


**子配置文件格式如下**

>子配置文件的名字位置取决于主映射文件中的map的值
```
key [-options] location
 
例：
share -fstype=ext4,rw :/dev/sda1
nfs -fstype=nfs,rw,sync 11.49.xxx.xxx:/nfs
```
- key：对于直接映射，表示挂载点，对于间接映射，和主配置文件中的mount-point拼成挂载点
- location,：被挂载的文件系统的位置，对于网络文件系统，使用`host:pathname`的形式。如果要挂载的文件系统以`/`开头，则需要`:`作为前缀
- options：一些可选选项，如下表

|  选项 |  说明 |
| ------------ | ------------ |
|  -fstype  | 如果文件系统不是默认的NFS类型，则使用该选项指定文件类型。|
|  -strict  |在挂载多个文件系统时使用，如果给出了这个选项，则当至少有一个文件系统不能被挂载时，所有的文件系统都不会被挂载。|
|...|...|


#### 典型配置案例

间接映射

```
# 主映射文件/etc/auto.master
# 格式如下：
# mount-point [map-type[,format]:]map [options]
/share /etc/auto.misc

# 子映射文件/etc/auto.misc
# 格式如下：
# key [-options] location

* -fstype=nfs,rw,sync 11.49.xxx.xxx:/&

```
>其中子配置文件的key中使用了*通配符，在/share目录下尝试cd进入abc时，会尝试挂载11.49.xxx.xxx:/abc

直接映射
```
# 主映射文件/etc/auto.master
# 格式如下：
# mount-point [map-type[,format]:]map [options]
/- /etc/auto.misc

# 子映射文件/etc/auto.misc
# 格式如下：
# key [-options] location

/data/lhd -fstype=nfs,rw,sync 11.49.xxx.xxx:/lhd

```
